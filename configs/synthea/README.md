# Synthea UAE configuration

Synthetic data generated by Synthea — not real patient records.

`synthea/` is gitignored, so everything UAE-specific lives here and is copied into
`synthea/src/main/resources/` by `install_uae_resources()` (called by
`run_synthea_uae()`) before each run.

| File | Purpose |
|---|---|
| `build_uae_geography.py` | All demographic assumptions → `resources/geography/**`, `resources/providers/uae/*`, `resources/payers/uae/*` |
| `build_uae_modules.py` | GMF modules → `resources/modules/uae_metabolic_risk.json`, `uae_heat_illness.json` |
| `../synthea_uae.properties` | Synthea overrides (pass with `-c`, **before** `-p`) |

Regenerate after editing either builder:

```bash
python configs/synthea/build_uae_geography.py
python configs/synthea/build_uae_modules.py
```

## Things that differ from a naive config

- Synthea's demographics loader only reads its US-Census schema (18 five-year age
  bands, 5 races + HISPANIC, 10 income bands in $k, 4 education levels). The UAE
  9-band ages and 6 ethnicities are inputs mapped onto that schema; the ethnicity
  shares are also written as extra columns, and the parser recovers a per-patient
  UAE ethnicity from race + city shares (`assign_uae_ethnicity`).
- A non-US geography also needs zipcodes, timezones, providers (filtered by state
  abbreviation `AE`) and payer eligibility files with a UAE row — all generated here.
  Facilities are generic and labelled "(Synthetic)".
- `generate.geography.foreign_birthplace.default_city` is kept from the spec but is
  not a Synthea property and has no effect.

## Calibration (seed 42, 10k population, adults ≥18 alive, active condition)

Synthea's stock metabolic models are US-calibrated and already exceed the UAE
targets for obesity and prediabetes; a top-up module can only add prevalence, so
those top-ups are 0 and the achieved figure is reported as-is.

| Hypertension | ~24% | 24.1% | |

| Prediabetes | ~20% | 34.7% | stock Synthea baseline alone exceeds target |
