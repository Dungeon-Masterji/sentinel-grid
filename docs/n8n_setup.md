# n8n alert routing: setup

Sentinel Grid hands every alert to an **n8n** workflow that routes it to the responsible
role, waits for an acknowledgement and escalates if none comes. The workflow is versioned
in this repo as `ops/n8n/workflows/alert_routing.json`, generated by
`ops/n8n/build_workflow.py` from `configs/ops_channels.yaml`.

```
alert pipeline (every 15 min) ─┐                     ┌─ watch    → auto-log ack ("n8n-auto-log")
                               ├─ POST webhook ─ n8n ┼─ advisory → notify owner → wait 15 min → ack? done : escalate
POST /api/ops/replay_alert ────┘                     └─ warning  → notify owner + escalation contact
                                                                    → wait escalation_if_no_ack_in_minutes
                                                                    → ack? done : emirate operations lead
            every step ──► POST {callback_base}/api/ops/events ──► /ops diagram + GET /api/ops/audit
```

Who gets notified is **resolved before the webhook** (`packages/pipelines/ops/notify.py`)
and arrives in the payload: `channels.owner`, `channels.supervisor` (the owner's
`escalates_to`) and `channels.emirate_ops_lead`. Changing a channel never means editing the
workflow.

## 1. Run n8n locally (Docker)

```bash
make n8n-up        # docker run -d --name n8n -p 5678:5678 -v n8n_data:/home/node/.n8n n8nio/n8n
make n8n-import    # regenerate the JSON, import it, publish it, restart n8n
```

The production webhook is then `POST http://localhost:5678/webhook/sentinel-grid/alert`.
Open http://localhost:5678 to watch executions (Executions tab). The canvas sticky notes
are colour-coded by role group (site, safety & HR, health, regulators, emirate).

Smoke test with the local API (needs `.env`):

```bash
make demo-api      # API on :8000, N8N_WEBHOOK_URL=localhost n8n, callbacks via host.docker.internal
curl -X POST "localhost:8000/api/ops/replay_alert/<alert_id>?demo=true&as_severity=warning"
curl "localhost:8000/api/ops/audit?alert_id=<alert_id>"
```

`demo=true` shortens every wait to 10 s. `as_severity` rehearses an alert at another
severity, and the payload and every audit row are then marked `rehearsal: true`.

## 2. Channels (configs/ops_channels.yaml)

No phone numbers or chat ids live in the repo. Each role has:

* `url_env`, e.g. `OPS_CH_SITE_SUPERVISOR`: set it to a Slack incoming webhook, a Telegram
  bot `sendMessage` URL, a Teams connector or an SMS gateway, and that wins;
* otherwise a public **webhook.site** inbox, so judges can watch hits land:
  https://webhook.site/#!/view/83dbf5dd-7ef6-4a16-bcad-2b0c18b09845 (one path per role).
  Free webhook.site URLs expire after 7 days (this one on 2026-11-25). Create a new one with
  `curl -X POST https://webhook.site/token` and replace `demo_base`.

The API never shows env-configured URLs in full (`/api/ops/channels` and the audit log show
the host only), because Slack webhook URLs are secrets.

## 3. Expose the local webhook (ngrok or cloudflared)

Azure and GitHub Actions cannot reach `localhost`. During the pitch n8n runs on the
laptop, so expose it:

```bash
make demo-tunnel   # needs ngrok (brew install ngrok/ngrok/ngrok) or cloudflared (brew install cloudflared)
```

It prints the public webhook URL plus the commands below, ready to paste.

## 4. Point Azure (and the 15-minute pipeline) at it

```bash
# the API: POST /api/ops/replay_alert sends here
az webapp config appsettings set -n sentinel-grid-api -g <resource-group> \
  --settings N8N_WEBHOOK_URL=https://<tunnel>/webhook/sentinel-grid/alert \
             OPS_CALLBACK_TOKEN=<random string>

# the alert pipeline: every new alert (or escalation) is POSTed after each run
gh secret set N8N_WEBHOOK_URL --body https://<tunnel>/webhook/sentinel-grid/alert
gh secret set OPS_CALLBACK_TOKEN --body <same random string>
```

* `OPS_CALLBACK_BASE` (optional) is the base URL n8n calls back. The API defaults to its own
  public URL, and the pipeline uses `https://sentinel-grid-api.azurewebsites.net`. For a
  local API with n8n in Docker use `http://host.docker.internal:8000` (what `make demo-api`
  sets).
* `OPS_CALLBACK_TOKEN`: when set, `/api/ops/events` requires header `X-Ops-Token`. The
  token travels to n8n inside the payload, because n8n 2.x blocks `$env` in expressions.
* With `N8N_WEBHOOK_URL` unset, the pipeline skips routing and logs it, and
  `replay_alert` answers `sent: false, simulate: true`.

## 5. When the network dies mid-demo

The `/ops` page never depends on n8n answering. If the replay POST fails, the webhook is
unset, or n8n does not report a step within 8 s, the page **simulates** the same routing
plan locally (deterministically, with the same waits). It labels every simulated step
`simulated`, still branches on a real "Acknowledge as owner" click, and still records the
real send attempt in the audit log. If the API itself is unreachable it falls back to an
offline demo alert.

## Ledgers behind GET /api/ops/audit

| File | Written by | Holds |
|---|---|---|
| `alerts/sends.jsonl` | pipeline (`fusion/alerts.py` → `ops/notify.py`), carried on the `data/processed/alerts` branch | one line per webhook POST; an alert is re-sent only when its severity rises |
| `ops_sends.jsonl` | API `replay_alert` | demo/replay sends |
| `ops_events.jsonl` | n8n → `POST /api/ops/events` | each routing step: received, routed, logged, notified_owner, acked, escalated, acked_after_escalation, emirate_ops_lead |
| `acks.jsonl` | `POST /api/alerts/{id}/ack` (people, and n8n's auto-log) | acknowledgements |

## Security gaps (hackathon)

`replay_alert` has no auth (it only re-sends public alert text to pre-configured
channels). `/events` is protected only by the optional shared token, and acks are
unauthenticated (see `routers/alerts.py`). Put real auth in front of all three before
production use.
